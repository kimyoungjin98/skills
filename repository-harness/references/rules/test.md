# 테스트

## 공통

- 기능 구현·수정 시 변경한 동작을 검증하는 테스트 코드를 함께 작성·수정하고 실행. 테스트 작성 여부를 별도로 묻지 않음
- 사용자가 테스트 내용을 지정한 경우 해당 내용을 반영. 지정하지 않은 경우 요청한 작업 내역, 기대 동작, 기존 코드와 정책을 기준으로 테스트 시나리오를 도출하여 작성
- 기존 환경에 테스트 도구가 구축되어 있을 경우 해당 도구를 사용(사용자의 요청이 있을 경우 다른 도구로 변경이 가능)
- 테스트 도구가 없을 경우 언어와 실행 환경에 맞게 구성 : JavaScript/TypeScript는 `vitest`, Python은 `pytest`를 기본값으로 사용
- 문서나 단순 스타일 수정은 관련 링크, 내용, 화면을 검증하며 불필요한 테스트 도구를 추가하지 않음
- [코드베이스아키텍처](code-base.md)
- 대상 프로젝트 문서·스크립트·설정·CI와 변경 영역에서 검증 명령과 범위를 도출하고 근거를 계획에 기록. 명령이 없으면 해당 검증이 가능한지 확인하고 미구축 상태를 보고
- 변경된 동작과 회귀 가능성이 있는 부분을 검증하며, 커버리지 수치만으로 통과 여부를 판단하지 않음
- 커버리지 기준이 있는 프로젝트는 기존 기준을 적용. 기준이 없으면 임의의 수치를 강제하지 않음

- 모델 검증과 자동화 재검증에는 동일한 테스트 전용 환경과 쓰기 가능한 캐시·산출물 경로 제공. 운영 비밀정보는 전달하지 않음
- 검사 생략, 경고 제한 완화, 실패 무시로 통과한 것처럼 만들지 않음
- 서브모듈이 있으면 초기화·인증과 내부 변경 여부를 확인하고 검증 범위에 반영. 실패 작업의 변경을 보존하고 브랜치·기준 커밋 확인 후 재개

## 테스트 코드 작성

- 구현 계획에서 요청한 작업과 테스트 시나리오·기대 결과를 연결하고 정상 동작, 실패 조건, 경계값과 회귀 가능성을 확인. 해당하는 항목을 테스트 코드에 반영
- 기존 테스트로 검증되는 동작은 재사용하고 변경으로 달라진 기대 결과나 누락된 시나리오를 추가·수정. 기존 테스트로 충분하면 해당 테스트와 근거를 기록하고 중복 테스트를 만들지 않음
- 버그 수정은 수정 전 문제를 재현하고 수정 후 통과하는 회귀 테스트를 작성
- 구현 내부의 호출이나 반환값을 그대로 따라 쓰기보다 사용자가 요청한 결과와 외부에서 확인 가능한 동작을 검증. 저장 기능은 저장 요청 성공뿐 아니라 이후 조회 결과도 확인
- 변경 범위에 맞게 단위·통합·사용자 흐름 테스트를 선택. API·DB·화면을 거치는 동작은 관련 경계와 최종 결과를 검증하고, 모든 변경에 모든 종류의 테스트를 강제하지 않음
- 테스트에 필요한 데이터와 환경을 재현 가능하게 준비하고 운영 데이터와 격리. 테스트 코드를 작성했더라도 실행하지 못했으면 미실행으로 기록
- 사용자가 테스트 작성을 제외하거나 대상 프로젝트 규칙이 범위를 제한하면 해당 지시를 우선하고 제외 범위와 근거를 기록. 문서나 단순 스타일 수정은 공통의 검증 기준 적용

## 변경별 검증

| 변경 | 필수 검증 |
| --- | --- |
| 문서 | 내용의 일관성, 상대 링크와 참조 파일 존재 여부 |
| 프론트엔드 | 설정된 lint, 타입 검사, 빌드, 관련 동작 테스트. 화면 변경 시 브라우저 검증 |
| 백엔드 | 설정된 lint, 타입 검사 또는 컴파일, 관련 동작 테스트 |
| DB | 격리된 테스트 DB에서 마이그레이션 적용, 기존 데이터와 제약조건에 미치는 영향 검증 |
| 공통 타입이나 패키지 | 변경한 패키지와 이를 사용하는 영역의 타입 검사, 빌드, 관련 테스트 |

## 실패 처리와 결과 기록

- 정적 검증·실제 실행 검증·수동 복구를 구분하고 각 검증의 실행 명령, 대상, 결과(통과/실패/미실행), 실패 또는 미실행 사유를 기록
- 작성·수정하거나 재사용한 테스트와 요청한 작업의 대응 관계를 PR에 기록하고, 검증하지 못한 시나리오와 다음 조치를 함께 보고
- 기존 실패인지 판단이 필요하면 기준 브랜치의 별도 작업 공간에서 동일 조건으로 확인. 확인할 수 없으면 원인 미확정으로 기록
- 변경으로 발생한 실패는 수정 후 관련 검증을 다시 실행
- 기존 실패가 남아 있으면 전체 통과로 보고하지 않고, 현재 변경의 검증 결과와 분리하여 보고
- 도구, 인증, 환경 부족으로 실행할 수 없으면 완료로 처리하지 않고 필요한 조치와 남은 검증을 보고. 발행 정책에 따른 Draft 전달은 별도 상태로 기록
- 브라우저 검증을 못 한 경우 코드 검토 결과로 화면 검증을 대체 통과시키지 않음

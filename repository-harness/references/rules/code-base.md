# 코드 베이스 규칙

## 가이드

- 모노레포(Nx, Turborepo... 등)의 구조일 경우 모든 사항을 고려
- 단일 레포(Frontend, Backend... 등)의 경우는 필요한 사항만 고려

## 공통

- 기존 프로젝트에 해당 구조를 반영할 경우 기존 프로젝트의 기술을 베이스로 한다(기술 변경은 사용자의 요청이 있지 않는 한 X)
- 하위 문서의 기술 지정은 신규 구성 시 기본값이며, 기존 프로젝트의 기술 유지 원칙을 우선
- 재사용성, 확장성, 유지보수성이 고려되어야 함
- 단순하고 직관적이어야함
- AI가 아닌 사람이 읽기 쉬운 구조여야함
- 나중을 고려한 오버 엔지니어링은 피해야 함
- 현재 요구사항을 빠르게 해결할 수 있는 구조여야 함

## File, Folder

- 도메인 별로 폴더를 분리해야 함
- 한 개의 컴포넌트,서비스 등에서 많은 로직이 이루어져서는 안됨(분리 필요)
- 한 폴더 내에 너무 많은 파일이 담겨있어 한 눈에 보기 힘든 구조는 피해야 함
- 폴더안에 폴더를 사용해서 사용자가 직관적으로 계층/도메인 등을 이해할 수 있어야 함

## Utils, Libs

- 공통으로 사용되는 (2곳 이상에서 사용) 유틸 또는 라이브러리는 전역으로 사용할 함수를 만들어 분리
- (모노레포 기준) 공용으로 사용되는 라이브러리, UI, 함수 모음 등은 `packages/...`로 분리

## DTO, Interface

- 런타임 경계를 넘는 공통 타입은 `packages/...`로 분리하여 관리
- 같은 타입을 `프론트`와 `백엔드` 양쪽에 중복 선언하지 않음
